From ticket to spec, without guesswork

Every story runs the same three-stage pipeline. Decisions are recorded. Open questions are resolved. Specs leave nothing to interpret.

Three skills, one workflow

Each skill handles a discrete phase. Run them in order or invoke any one independently.

/adr
<ticket-key> <requirements text>

Interviews you on every architectural decision a story requires — one question at a time, depth-first. Checks for contradictions with existing ADRs before starting. Writes the entry to arch/ADR.md.

  • 1Capture requirements verbatim into requirements.md
  • 2Scan ADR.md for contradictions before interviewing
  • 3Interview depth-first: one question, wait, continue
  • 4Write ADR entry: decisions, rationale, open questions
/resolve
<ticket-key>[, <ticket-key>, …]

Finds every Open Question left in one or more ADR entries and interviews you until each is resolved. Promotes each answer to a Decision and removes the question — leaving a clean, complete ADR.

  • 1Collect all Open Questions from each ticket's ADR
  • 2Interview per the same protocol — one question at a time
  • 3Add each answer as a Decision with rationale
  • 4Remove the question; delete section if empty
/tech-spec
<ticket-key>[, <ticket-key>, …]

Reads requirements.md and ADR.md for each ticket, cross-references the artifact manifest, and writes a fully self-contained technical specification. Every field, method, SOQL query, and flow step is explicit.

  • 1Block if any open questions remain (runs /resolve first)
  • 2Cross-reference artifacts.md to avoid duplicates
  • 3Write pedantic, zero-ambiguity spec: every field, SOQL, step
  • 4Update artifacts.md manifest with new artifacts

What gets created

All output lives under arch/ in your project root. Every file is append-safe — rerunning a skill overwrites only the affected entry.
